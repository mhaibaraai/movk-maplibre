## Introduction

`MaplibreSource` declaratively manages a maplibre-gl data source: it calls `addSource` when the map is ready, applies incremental updates when `source` changes (e.g. `setData` for geojson, `setTiles` for vector) instead of recreating the whole source, and safely removes it on unmount. Child layers reference the source by its `source="<sourceId>"` string, or simply nest inside it and omit `source`.

::tip{to="/docs/core/layer"}
A single source can be consumed by multiple layers simultaneously — this is the key advantage of an explicit `MaplibreSource` over an inline source inside `MaplibreLayer`.
::

### Nested Composition

`sourceId` is optional and generated from the source type (e.g. `geojson#1`). A layer nested inside `MaplibreSource` references it when `source` is omitted, and a `MaplibreTooltip` nested inside a layer binds to it when `layerId` is omitted — no hand-written ids required:

---

::note
Pass ids explicitly when you call id-based APIs in setup (e.g. `useFeatureState(layerId)`, `map.getLayer()`) or anchor with a string `beforeId`. Generated ids take the reserved form `<type>#<n>` (e.g. `fill#1`) and never collide with hand-written ids; do not use that form for explicit ids, or a development warning is logged.
::
